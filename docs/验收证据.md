## 五、本次修复的 4 个真实缺陷

### ① 音色 ID 猜错（我自己的 bug）

```
服务端拒绝：{"message":"voice cangshubao is not valid","code":"400"}
```
修正为 `cixingnansheng`。

### ② 工具定义在连接前下发，被静默丢弃

应用日志实证：
```
[WARN] [Realtime] 发送失败（未连接）: session.update
[INFO] [Realtime] 已下发 17 个工具定义
```
17 个工具定义**全部丢失**，模型无工具可调。
修正：改为在收到 `session.created` 之后再下发。

### ③ 打断时的正常回执被当成故障

```
[ERROR] [Realtime] 服务端 error 事件: invalid_request_error: no ongoing response to cancel
[INFO] [FSM] listening -> error （错误：no ongoing response to cancel）
```
用户打断时若恰无进行中的响应，服务端会回此错误 —— 属**正常情况**，但状态机被误推到 `error`。
修正：识别并忽略此回执，同时忽略 `commit when server vad`。

### ④ 端点与模型混搭导致 404

修正：实时语音 `/v1`，视觉 `/step_plan/v1`，均在配置中可改。
