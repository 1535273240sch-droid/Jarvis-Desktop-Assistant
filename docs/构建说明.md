# 构建说明

## 一、环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | 20 LTS 或更高（建议 22） | 已实测 22.14.0 |
| npm | 随 Node 附带 | 已实测 10.9.2 |
| 操作系统 | Windows 10/11 x64 | 打包 Windows 目标需在 Windows 上构建 |

> Orb 上游声明使用 pnpm 11。主工程用 npm 即可；仅在重装 `vendor/orb/node_modules` 时才需要 pnpm。

## 二、本地构建

```bash
npm install          # 主工程依赖（Electron、TypeScript、MCP、ws）
npm run build        # 四步，见下
npm start            # 启动应用
```

`npm run build` 执行 `scripts/build.mjs`，共四步：

1. **生成球体页** `node scripts/generate-orb.mjs` —— 经 Vite SSR 载入 `vendor/orb` 的 `orb-states.ts` 与 `code-export.ts`，导出六态页面并注入宿主桥接脚本，输出 `src/renderer/orb.html`。**只改 `orb.html` 会被本步覆盖**；改渲染逻辑的注意事项见 `docs/悬浮球-WebGPU-稳定性.md`。
2. **编译 TypeScript** `npx tsc -p tsconfig.json` —— 主进程 + preload + common 全部编译到 `dist/`。
3. **拷贝渲染资源** `src/renderer/` → `dist/renderer/`。
4. **校验产物** —— 确认 5 个关键文件存在，缺任意一个则构建失败（避免「构建成功但运行白屏」）。

### 免 PATH 运行器

`npm run <任务>` 由 npm 脚本外壳执行，需要 PATH 里有 `node`。报 `'node' 不是内部或外部命令` 时，
把 Node 安装目录加入 PATH，或直接用仓库内的运行器（不依赖 PATH）：

```bash
node scripts/run.mjs <build|start|selftest|dist|pack|typecheck|verify-mcp|verify-tools|verify-tasks|verify-orb|verify-briefing|verify-execution|verify-app-e2e>
```

### `vendor/orb/node_modules`

`vendor/orb` 需要自己的依赖（它用 Vite 做 SSR 加载）。缺失或损坏时用 pnpm 恢复：

```bash
cd vendor/orb
corepack pnpm install --ignore-scripts
```

> **不要用 robocopy / 复制粘贴搬运该目录**：pnpm 使用符号链接结构，普通复制会破坏链接，
> 导致 `Cannot find package 'rolldown'` 之类错误。

## 三、自测

```bash
npm run selftest
```

端到端自测（app:// 加载、球体就绪、六态切换、音频频段、状态机、WebGPU、配置脱敏、
危险命令识别、屏幕截图、活动窗口识别、面板窗口），并生成可视化取证截图到 `assets/`。

`node scripts/verify-mcp.mjs` 另做 MCP 协议验证：拉起 desktop-commander 子进程，
完成 initialize 握手、tools/list 发现与真实 tools/call 调用。

## 四、打包

```bash
npm run dist     # 完整打包（构建 + electron-builder NSIS）
npm run pack     # 只打包成目录（不生成安装包，便于快速验证）
```

产物：`release/Jarvis-Setup-<版本>-x64.exe`。

**`asarUnpack` 已收窄为仅解包原生模块**：`["**/*.node", "**/*.dll", "**/@vscode/ripgrep*/bin/rg.exe"]`。
历史上曾把整个 `node_modules` 全量解包，以规避外部 MCP 子进程（`spawn` 的独立进程）读不到
`app.asar` 内文件的问题；本版本按「只解包必须落在真实文件系统的原生模块」收敛，显著减小体积。
若日后外部 MCP 子进程报 `Cannot find module ...`，说明存在非原生依赖也需要解包，需用
`node scripts/verify-mcp.mjs` 与解包后的启动测试重新验证再调整范围，不要盲目全量解包。

## 五、CI 自动构建与发布

`.github/workflows/build-windows.yml` 在 `push main`、`pull_request` 与手动 dispatch 触发，构建 job 顺序执行
（PR 事件跳过发布与签名，仅做构建/回归校验）：

1. `npm ci` 安装主工程依赖；在 `vendor/orb` 执行 `pnpm install`；
2. 计算并写回版本号（见第六节）；
3. `npm run build`；
4. `node scripts/run.mjs verify-tools`；
5. `node scripts/run.mjs verify-tasks`；
6. `node scripts/run.mjs verify-orb`（悬浮球恢复链路，见 `docs/悬浮球-WebGPU-稳定性.md`）；
7. `node scripts/run.mjs verify-briefing`（信息简报，纯离线）；
8. `node scripts/run.mjs verify-execution`（长任务执行中断专项）；
9. `npm run dist -- --publish never` 打 NSIS 安装包；
10. 校验 `release/latest.yml`：`version` 必须等于本次写入的版本，且含 `sha512`（否则更新完整性校验失败）；
11. 上传产物（exe / latest.yml / blockmap）；非 PR 时由独立 release job 发布 GitHub Release（tag 为 `v<版本>`，一次构建一个 tag，不复用旧 tag）。

第 4~8 步任一失败即**阻断发布**。本机没有安装包所需的完整构建环境时，`verify-orb` 等回归脚本
直接读源码与仓库内已有的 `orb.html` 做断言，**不需要先跑构建**。

## 六、版本号规则

- **版本号必须是合法 semver（`x.y.z`）**：electron-builder 的 `normalizePackageData` 会用
  `semver.valid()` 校验，像 `1.0.0.8` 这种**四段式会被直接拒绝**（`Invalid version`）；
  也不能用 `1.0.0-8` 预发布形式——semver 语义下预发布小于正式版，会被 electron-updater 判为降级。
- 因此 CI 用 `github.run_number` **顶替 patch 段**，并与原有 patch **取 max**，保证单调递增。
- 必须改 `package.json` 本体：app 版本与 `latest.yml` 的 `version` 都源自它，
  只改 Release tag 名不会触发更新。
- 写入后再用仓库自带的 `semver` 自检一遍，不合法即失败；因此该步骤必须放在依赖安装之后。

## 七、可选代码签名

配置仓库 Secrets `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD` 后由 electron-builder 自动签名
（工作流映射为 `CSC_LINK` / `CSC_KEY_PASSWORD`）。未配置时安装会出现 SmartScreen 警告。

## 八、常见构建问题

| 问题 | 原因与解决 |
|---|---|
| `Cannot find package 'rolldown'` | `vendor/orb/node_modules` 的 pnpm 符号链接被破坏。删除后用 `corepack pnpm install` 重装 |
| `'node' 不是内部或外部命令` | Node 不在 PATH。把 `C:\Program Files\nodejs` 加入 PATH，或用 `node scripts/run.mjs <任务>` |
| 构建成功但运行时白屏 | 检查 `app://` 协议是否在 `app.whenReady()` 之前注册；用 `npm run selftest` 看具体失败项 |
| 打包后 MCP 报 `Cannot find module` | 说明有非原生依赖需解包：按报错把对应路径补进 `asarUnpack`（先不要盲目恢复全量 `**/node_modules/**`），并用 `node scripts/verify-mcp.mjs` 与解包后启动测试复验 |
| `Invalid version` | 版本号不是合法 semver（例如四段式）。见第六节 |
| `tsc` 报错 | 本项目已实测零错误；改过代码后按提示修复，不要用 `--noEmitOnError false` 绕过 |
