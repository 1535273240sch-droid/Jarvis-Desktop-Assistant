# 构建说明

## 一、环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | 20 LTS 或更高（建议 22） | 已实测 22.14.0 |
| npm | 随 Node 附带 | 已实测 10.9.2 |
| 操作系统 | Windows 10/11 x64 | 打包 Windows 目标需在 Windows 上构建 |

> Orb 上游声明使用 pnpm 11。本项目主工程用 npm 即可；
> 仅在需要重新安装 `vendor/orb/node_modules` 时才需要 pnpm。

## 二、首次构建

```bash
npm install          # 安装主工程依赖（含 Electron、TypeScript、MCP、ws）
npm run build        # 生成球体页面 + 编译 TS + 拷贝资源 + 校验产物
npm run selftest     # 可选：无人值守自测，并生成截图
npm start            # 启动应用
```

### ⚠️ 前提：`node` 必须在 PATH 中

本项目的构建脚本内部用**当前 Node 解释器的绝对路径**调用子步骤，
所以直接 `node scripts/build.mjs` 在 Node 不在 PATH 时也能跑通。

但 `npm run build` 这类命令由 npm 自身的脚本外壳执行，**它需要 PATH 里有 `node`**。
若报 `'node' 不是内部或外部命令`，把 Node 安装目录加入 PATH 即可（本机实测过这一情况）：

```powershell
# 临时（当前终端有效）
$env:PATH = "C:\Program Files\nodejs;" + $env:PATH

# 永久
[Environment]::SetEnvironmentVariable("PATH", "C:\Program Files\nodejs;" + [Environment]::GetEnvironmentVariable("PATH","User"), "User")
```

或用仓库内提供的免 PATH 脚本：

```bash
node scripts/build.mjs      # 不依赖 PATH
node scripts/run.mjs start  # 等价于 npm start
node scripts/run.mjs selftest
node scripts/run.mjs dist
```

### 关于 `vendor/orb/node_modules`

`vendor/orb` 需要它自己的依赖才能生成导出页（它用 Vite 做 SSR 加载）。
如果该目录缺失或损坏，用 pnpm 恢复：

```bash
cd vendor/orb
corepack pnpm install --ignore-scripts
```

> **注意**：不要用 `robocopy` / 复制粘贴的方式搬运 `vendor/orb/node_modules`。
> pnpm 使用符号链接结构，普通复制会破坏链接，导致 `Cannot find package 'rolldown'` 之类的错误。

## 三、构建流程详解

`npm run build` 执行 `scripts/build.mjs`，共四步：

1. **生成球体页面** `node scripts/generate-orb.mjs`
   - 通过 Vite SSR 载入 `vendor/orb` 的 `orb-states.ts` 与 `code-export.ts`
   - 调用 `createPresetOrbStateConfiguration("siri")`（siri 支持音频响应）
   - 调用 `createWebExport(config, "idle")` 得到自包含 HTML
   - 注入宿主桥接脚本（就绪上报、错误转发、鼠标穿透、拖拽）
   - 输出到 `src/renderer/orb.html`

2. **编译 TypeScript** `npx tsc -p tsconfig.json`
   - 主进程 + preload + common 全部编译到 `dist/`

3. **拷贝渲染资源** `src/renderer/` → `dist/renderer/`

4. **校验产物**：确认 5 个关键文件存在，缺任意一个则构建失败（避免出现"构建成功但运行白屏"）

## 四、打包

```bash
npm run dist     # 完整打包（构建 + electron-builder NSIS）
npm run pack     # 只打包成目录（不生成安装包，便于快速验证）
```

产物：`release/Jarvis-Setup-1.0.0-x64.exe`（约 104 MB）

### 打包配置要点（`package.json` 的 `build` 字段）

```json
"asarUnpack": ["**/node_modules/**"]
```

**这一项是必须的，且范围要开到全部 node_modules。**

原因：MCP 服务器是以**独立子进程**方式启动的（`spawn`），
而 `app.asar` 内的文件无法被外部进程读取。由于 DesktopCommander 的依赖树里有
深层的传递依赖（例如 `@opendocsg/pdf2md`），只解包 `@wonderwhy-er/**` 会导致子进程
启动时报 `Cannot find module '@opendocsg/pdf2md/lib/util/pdf'` 而崩溃。

> 这是本项目实际踩过的坑，已修复。若日后为了减小体积想收窄 `asarUnpack`，
> 必须用 `node scripts/verify-mcp.mjs` 与解包后的启动测试重新验证。

### 代码签名

当前未配置签名，安装时会出现 SmartScreen 警告。如需签名，在 `build.win` 下增加
`certificateFile` 与 `certificatePassword`，或在 CI 中通过环境变量注入。

## 六、架构说明

### 进程与职责划分

```
主进程（Electron main）
  ├── 所有外部网络调用（实时语音 WebSocket、视觉 HTTP）—— 渲染进程永不接触 API Key
  ├── 六态状态机（唯一真源，含看门狗超时）
  ├── MCP 客户端（stdio 子进程）+ 工具白名单
  ├── 安全闸门（危险命令拦截 + 人工确认 + 审计日志）
  ├── 原生能力（截图、活动窗口识别、鼠标键盘）
  └── 球体控制层（只能调 liquidOrb 的 4 个方法）

渲染进程（renderer）
  ├── orb.html   球体页面（由 Orb 导出，含桥接脚本）
  └── panel.html 聊天面板 + Web Audio（采集/播放/频谱）

preload
  └── contextBridge 暴露受限 API，不透传 ipcRenderer
```

### 为什么音频要在渲染进程做

`AudioContext` 只在渲染进程可用。所以：
- **上行**：面板采集麦克风 → 重采样 24kHz 单声道 → PCM16 → base64 → 经 IPC 交主进程 → 发 WebSocket
- **下行**：主进程收到音频分片 → 经 IPC 交面板 → Web Audio 排队播放
- **打断**：主进程通知面板立即清空播放缓冲（本地静音），然后才 `response.cancel`
- **球体驱动**：面板算好 `low/mid/high/all` 四频段（含非对称平滑）→ 交主进程 → 喂给球体

### 为什么屏幕理解要独立通道

实时语音 WebSocket 的 `modalities` **固定为 `["text","audio"]`，不支持图像**。
因此"看屏幕"必须另开一条 HTTP 通道：截图 → 视觉模型 → 文本 → 回注实时会话。

### 关键启动顺序（不能调换）

1. WebGPU 命令行开关
2. `registerSchemesAsPrivileged`（**必须早于 `app.whenReady()`**，否则打包后 `app://` 失效 → 白屏）
3. `whenReady` → 注册协议处理器 → 建窗口 → 加载 `app://orb/orb.html` → 注册 IPC → 建托盘

## 七、常见构建问题

| 问题 | 原因与解决 |
|---|---|
| `Cannot find package 'rolldown'` | `vendor/orb/node_modules` 的 pnpm 符号链接被破坏。删除后用 `corepack pnpm install` 重装 |
| `'node' 不是内部或外部命令` | Node 不在 PATH。把 `C:\Program Files\nodejs` 加入 PATH |
| 构建成功但运行时白屏 | 检查 `app://` 协议是否在 `whenReady` 之前注册；用 `npm run selftest` 看具体失败项 |
| 打包后 MCP 报 `Cannot find module` | `asarUnpack` 范围不够，改为 `**/node_modules/**` |
| `tsc` 报错 | 本项目已实测零错误。若你改过代码后报错，按提示修复；不要用 `--noEmitOnError false` 绕过 |
